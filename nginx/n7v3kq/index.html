nginx 常用的变量

# 1.变量基础

nginx 里所有变量都以 $ 开头。变量分两类：内置变量（由 nginx 各模块提供，只读）和自定义变量（用 set / map 定义）。

# 自定义变量
set $my_flag 0;
if ($http_user_agent ~* "bot") {
    set $my_flag 1;
}

# map 定义变量：根据另一个变量取值，性能比 if 好
map $http_user_agent $is_bot {
    default 0;
    ~*bot   1;
}

# 变量可以在字符串里拼接
add_header X-Flag "$my_flag-$is_bot";

几个语法要点：

  1. 变量在字符串中可直接用 $name，需要和后续字符分隔时用 ${name}，如 ${host}_suffix；
  2. 内置变量名不能被 set 覆盖（会报 the duplicate "xxx" variable）；
  3. 变量是惰性求值的：只有被用到（日志、header、指令参数）时才会计算。

⚠️ 常见误解：nginx 没有 $redirect_uri 这个内置变量。它通常来自 OAuth2 的 redirect_uri 查询参数，要用 $arg_redirect_uri 取。详见第 5 节。

# 2.URI 与请求行

以请求 GET /search?q=nginx%20tutorial&page=2 HTTP/1.1（Host: example.com:8080）为例：

变量 含义 示例值
$request 完整请求行（原始） GET /search?q=nginx%20tutorial&page=2 HTTP/1.1
$request_method 请求方法 GET
$request_uri 原始 URI，含查询串，不解码、不规范化 /search?q=nginx%20tutorial&page=2
$uri 当前 URI，已解码、已规范化、不含查询串 /search
$document_uri $uri 的别名 /search
$args / $query_string 查询串 q=nginx%20tutorial&page=2
$is_args 有查询串则为 ?，否则为空 ?
$arg_q 指定查询参数（已 URL 解码） nginx tutorial
$request_filename root/alias + URI 拼出的物理路径 /var/www/html/search
$document_root 当前 location 的 root 值 /var/www/html
$realpath_root 解析符号链接后的 root /data/www/html
$request_body 请求体（需 proxy_pass/fastcgi 上下文且已读入内存） {"a":1}
$request_body_file 请求体落盘的临时文件路径 /var/lib/nginx/body/0000000001
$content_length 请求头 Content-Length 42
$content_type 请求头 Content-Type application/json
$request_length 请求总字节数（请求行 + 头 + 体） 512
$request_completion 请求是否正常结束，正常为 OK OK

# 2.1 $uri 与 $request_uri 的区别 🔥

这是最容易被搞混的一对：

  • $request_uri 永远是客户端发来的原始串，经过 rewrite、internal redirect、try_files 都不会变；
  • $uri 会随着内部重写变化，且已解码、已规范化（//a//b → /a/b，%20 → 空格）。
location /a {
    rewrite ^/a(.*)$ /b$1 last;   # 内部重写
}

# 访问 /a/foo?x=1
# $request_uri  → /a/foo?x=1
# $uri（在 /b 的 location 里）→ /b/foo

# 3.Host 与域名

变量 含义 示例值
$host 取值优先级：请求行 host > Host 头 > server_name；转小写、去端口 example.com
$http_host 原始 Host 头，可能带端口、可能为空 example.com:8080
$server_name 匹配到的 server 块名 example.com
$server_port 服务端口 8080
$server_addr 服务器 IP 10.0.0.5
$server_protocol 协议版本 HTTP/1.1 / HTTP/2.0
$scheme 协议名 https
$https HTTPS 时为 on，否则为空 on

# 3.1 $host 与 $http_host 的区别 🔥

  • $host 不带端口，且当请求没带 Host 头时会退化为 server_name；
  • $http_host 原样返回 Host 头，没带就是空。
# 拼对外跳转地址 → 用 $host（不会出现 example.com:8080 这种尾缀）
return 302 $scheme://$host/new-path;

# 原样透传给后端 → 用 $http_host（保留客户端的端口和大小写）
proxy_set_header Host $http_host;

# 4.1 三个万能前缀 🔥

记住这三条规则，就不用背变量名了：

前缀 取值来源 例子
$http_xxx 请求头（去掉连字符、转小写） $http_accept_language、$http_authorization
$sent_http_xxx 响应头 $sent_http_content_type → text/html; charset=utf-8
$arg_xxx 查询参数（已解码） $arg_page、$arg_redirect_uri
$cookie_xxx Cookie $cookie_token
$upstream_http_xxx 上游返回的响应头 $upstream_http_location

注意：$http_ 取不到的请求头（比如名字里带下划线的、或超过 32 个字符的）会返回空串。

# 5.纠正：$redirect_uri 并不存在

nginx 内置变量里没有 $redirect_uri。它只是 OAuth2 授权流程里的一个标准查询参数名。

# 请求：/callback?code=abc&redirect_uri=https%3A%2F%2Fexample.com%2Fhome
$arg_redirect_uri   # → https://example.com/home  （注意已 URL 解码）
$arg_code           # → abc
1
2
3

直接把它拼进跳转会构成开放重定向漏洞（攻击者传任意站外地址，你的站点就成了钓鱼跳板）。必须做白名单校验：

# 只允许跳到自己的域名，其余一律回首页
map $arg_redirect_uri $safe_redirect {
    default                     /;
    "~^https?://example\.com/"  $arg_redirect_uri;
}

server {
    location /callback {
        return 302 $safe_redirect;
    }
}

# 7.代理与上游 🔥

# 7.1 HTTP 上游（$upstream_*）

这组变量只有在请求确实经过了 proxy_pass 之后才有值。

变量 含义 示例值
$upstream_addr 实际上游地址；重试/多上游时用 , 分隔 10.0.0.10:8080 / 10.0.0.10:8080, 10.0.0.11:8080
$upstream_status 上游返回的状态码，与 $upstream_addr 逐项对应 200 / 502, 200
$upstream_response_time 上游耗时（建连到收到响应结束） 0.012 / 0.001, 0.010
$upstream_header_time 建连到收到响应头的耗时（1.11.4+），即 TTFB 0.008
$upstream_connect_time 与上游建立 TCP 连接（含 TLS 握手）的耗时（1.9.1+） 0.001
$upstream_bytes_sent 发给上游的字节数（1.15.0+） 356
$upstream_bytes_received 从上游收到的字节数（1.15.0+） 2048
$upstream_http_xxx 上游返回的任意响应头 $upstream_http_content_type → application/json
$upstream_trailer_xxx 上游 trailer 头（1.13.10+） —

# $status 与 $upstream_status 的区别

前者是 nginx 返回给客户端的最终状态，后者是上游返回的状态。两者都可能为空或不同：

现象 含义
$status=502 且 $upstream_status=- nginx 根本没连上上游，问题在网络/上游未启动，不是后端返回了 502
$status=200 且 $upstream_status=502, 200 第一个上游失败，proxy_next_upstream 重试成功

# 7.2 代理目标与转发头

变量 含义 示例值
$proxy_host 由 proxy_pass 推导出的目标 host backend / 127.0.0.1
$proxy_port 目标端口（未写则 80/443） 8080
$proxy_add_x_forwarded_for 有 XFF 则追加 $remote_addr，否则等于 $remote_addr 198.51.100.1, 203.0.113.7
$realip_remote_addr realip 模块改写之前的原始客户端地址 203.0.113.7
$realip_remote_port 同上，原始端口 54321
location /api/ {
    proxy_pass http://backend;
    proxy_set_header Host              $http_host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

# 7.4 PROXY protocol

仅在 listen ... proxy_protocol 启用时可用。

变量 含义 示例值
$proxy_protocol_addr 真实客户端地址（来自 PROXY 头） 203.0.113.7
$proxy_protocol_port 真实客户端端口 54321
$proxy_protocol_server_addr 代理服务器自身地址 10.0.0.1
$proxy_protocol_server_port 代理服务器自身端口 443
$proxy_protocol_tlv_xxx v2 TLV 字段（1.13.11+），如 alpn、authority、unique_id、ssl h2

典型用法是先还原真实 IP，再取 $remote_addr：

server {
    listen 443 ssl proxy_protocol;

    set_real_ip_from 10.0.0.0/8;
    real_ip_header   proxy_protocol;

    # 此处的 $remote_addr 已经是真实客户端 IP
    add_header X-Client-IP $remote_addr;
}

# 8.实战：一个能定位问题的日志格式

log_format main '$remote_addr - $remote_user [$time_local] '
                '"$request" $status $body_bytes_sent '
                '"$http_referer" "$http_user_agent" '
                'host=$host port=$server_port '
                'up=$upstream_addr ust=$upstream_status '
                'rt=$request_time urt=$upstream_response_time '
                'ct=$upstream_connect_time ht=$upstream_header_time '
                'cache=$upstream_cache_status rid=$request_id';

access_log /var/log/nginx/access.log main;

# 8.1 排查慢请求的判断顺序

urt=-        → 上游根本没响应，纯连接层故障（继续看 ct 和网络）
ust=-        → nginx 没拿到上游状态码，同上
ct  大       → 上游建连慢，多半是 SYN 重传 / 上游过载
ht  大 urt 大 → 上游处理慢，直接去查后端
rt - urt 大   → nginx 自身或客户端侧慢（带宽、慢客户端、gzip 压缩等）

$request_time 与 $upstream_response_time 的差值，就是 nginx 自身开销 + 网络等待。遇到"接口慢但后端说很快"，第一个该看的就是它。

# 9.易错点汇总

  1. $redirect_uri 不存在 → 用 $arg_redirect_uri，并做白名单防开放重定向。
  2. $host 不带端口，$http_host 带端口；拼对外 URL 用 $host，原样透传用 $http_host。
  3. $request_uri 不解码，$uri 已解码且会随内部重写变化。
  4. $upstream_addr / $upstream_status / $upstream_response_time 都是列表，发生 proxy_next_upstream 重试时会变成 , 分隔的多项，监控脚本不能当单值比较。
  5. - 不等于 0：$upstream_response_time=- 表示"没有上游响应"，做耗时统计时必须和 0.000 分开处理，否则会污染平均值。
  6. $proxy_host 不能用来拼对外 URL，它来自 proxy_pass，可能只是一个 upstream 名字（如 backend）。
  7. HTTP 和 stream 模块的同名变量含义不同（$upstream_addr、$bytes_sent 等），日志格式不要混用。
  8. $binary_remote_addr 才是限流该用的，$remote_addr 是字符串，limit_req_zone 里用它会浪费内存。
